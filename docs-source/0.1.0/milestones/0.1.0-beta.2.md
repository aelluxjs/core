# Aellux 0.1.0 Beta 2

**Status:** Planejado  
**Versão alvo:** `0.1.0-beta.2`  
**Versão anterior:** `0.1.0-beta.1`

## Objetivo geral

Transformar a validação funcional obtida na primeira beta em uma base repetível de qualidade para uso público. Esta versão deve ampliar a cobertura de navegadores, automatizar os gates de integração, reduzir dependências externas dos testes e tornar mais objetivas as garantias de compatibilidade, desempenho, segurança e manutenção.

## Escopo obrigatório

### [ ] Integração contínua

- [ ] Criar pipeline de CI para instalação, build e testes.
- [ ] Executar `npm run build` em ambiente limpo.
- [ ] Executar `npm run test:browser` automaticamente.
- [ ] Executar `npm pack --dry-run` e validar os arquivos publicados.
- [ ] Executar `git diff --check` ou verificação equivalente.
- [ ] Bloquear integração quando qualquer gate obrigatório falhar.

### [ ] Matriz de navegadores

- [ ] Automatizar cenários em Chromium.
- [ ] Automatizar cenários em Firefox.
- [ ] Automatizar cenários em WebKit.
- [ ] Definir versões mínimas oficialmente testadas.
- [ ] Validar ao menos um ambiente mobile representativo.
- [ ] Separar suporte comprovado de compatibilidade apenas esperada.

### [ ] Validação Legacy real

- [ ] Definir os ambientes Legacy que permanecem relevantes para o projeto.
- [ ] Executar o boot ES5 e o orchestrator Legacy fora do modo forçado de um navegador Modern.
- [ ] Validar os polyfills compartilhados nas APIs usadas pelo Core.
- [ ] Confirmar carregamento de Extensions Modern-only, Legacy-only e Modern + Legacy.
- [ ] Documentar limitações específicas encontradas por ambiente.
- [ ] Revisar o tamanho e o custo de inicialização dos bundles Legacy.

### [ ] Testes do Core

- [ ] Adicionar testes unitários para helpers internos.
- [ ] Testar normalização de nomes, atributos, eventos e perfis `builds`.
- [ ] Testar diagnostics e seus códigos sem depender do console.
- [ ] Testar concorrência e cache das Promises de Extensions.
- [ ] Testar erros em `init`, `mount`, `unmount` e `destroy` separadamente.
- [ ] Testar limpeza do scheduler, observers, listeners e handlers de assets.
- [ ] Adicionar cenário prolongado para detectar crescimento indevido de memória.

### [ ] Lifecycle lazy

- [ ] Decidir se a Extension deve sair do índice lazy no início do carregamento ou após inicialização bem-sucedida.
- [ ] Alinhar implementação, documentação e milestone à decisão.
- [ ] Garantir retry previsível quando o carregamento falhar.
- [ ] Garantir que múltiplos elementos usando o mesmo seletor compartilhem uma única Promise.
- [ ] Cobrir carregamento, falha, retry e destruição com testes dedicados.

### [ ] Integração com Bootstrap

- [ ] Substituir dependência exclusiva de CDN por fixture local versionada nos testes.
- [ ] Validar componentes Bootstrap exibidos dinamicamente.
- [ ] Validar coexistência de listeners com Bootstrap JavaScript.
- [ ] Testar modal, offcanvas, collapse e tabs como casos representativos.
- [ ] Confirmar foco, teclado e desmontagem ao remover conteúdo dinâmico.
- [ ] Documentar exatamente o escopo da compatibilidade testada.

### [ ] Desempenho e tamanho

- [ ] Registrar tamanho normal e comprimido dos artefatos principais.
- [ ] Definir orçamento para boot, orchestrator, full e Legacy.
- [ ] Medir tempo de boot nos modos `basic` e `full`.
- [ ] Medir `$ae.update(root)` em documentos pequenos e grandes.
- [ ] Avaliar custo de observers e CSS adaptativo.
- [ ] Falhar o CI quando um orçamento aprovado for excedido sem justificativa.

### [ ] Segurança e cadeia de fornecimento

- [ ] Automatizar auditoria das dependências de build.
- [ ] Revisar manipulação de URLs de scripts e estilos.
- [ ] Documentar compatibilidade e requisitos para CSP.
- [ ] Avaliar publicação de hashes SRI para artefatos de CDN.
- [ ] Criar política de reporte de vulnerabilidades.
- [ ] Revisar riscos de Extensions de terceiros executadas no mesmo contexto global.

### [ ] Licenças e distribuição comercial

- [ ] Inventariar licenças das dependências incorporadas aos bundles Legacy.
- [ ] Confirmar preservação dos avisos obrigatórios nos arquivos minificados.
- [ ] Avaliar necessidade de arquivo `NOTICE` ou relatório de terceiros.
- [ ] Validar novamente o conteúdo de `npm pack`.
- [ ] Definir estratégia inicial de CDN, cache e versionamento imutável.
- [ ] Documentar procedimento de rollback de uma publicação.

### [ ] Acessibilidade

- [ ] Definir requisitos mínimos de acessibilidade para Extensions oficiais.
- [ ] Testar navegação por teclado nos exemplos interativos.
- [ ] Testar preservação e restauração de foco após atualizações de DOM.
- [ ] Validar estados `aria-busy`, loaders e conteúdo aguardando montagem.
- [ ] Verificar preferências de movimento, contraste e esquema de cores.
- [ ] Registrar responsabilidades do Core e das Extensions.

### [ ] Governança da API

- [ ] Classificar APIs públicas, experimentais e internas.
- [ ] Definir política SemVer para a linha beta.
- [ ] Definir processo de depreciação e remoção.
- [ ] Documentar critérios para promover uma Extension ao Core.
- [ ] Avaliar declarações TypeScript para APIs públicas.
- [ ] Criar checklist de revisão para Extensions de terceiros.

### [ ] Documentação e exemplos

- [ ] Atualizar a matriz de compatibilidade com resultados reais.
- [ ] Separar claramente garantias, expectativas e itens experimentais.
- [ ] Criar exemplo de Extension de terceiro construída fora do Core.
- [ ] Documentar CI, segurança, CSP, CDN e rollback.
- [ ] Revisar exemplos para funcionamento sem conexão quando aplicável.
- [ ] Atualizar README, changelog e documentação de release.

## Critérios de aceitação

- [ ] Build, testes e verificação de pacote executam automaticamente em CI.
- [ ] Os cenários obrigatórios passam em Chromium, Firefox e WebKit.
- [ ] O suporte Legacy publicado corresponde a ambientes realmente testados.
- [ ] O comportamento do índice lazy e de retry está definido e coberto.
- [ ] A integração Bootstrap não depende exclusivamente de CDN.
- [ ] Existem limites registrados para tamanho e desempenho dos principais artefatos.
- [ ] Dependências e licenças incorporadas foram auditadas.
- [ ] Os requisitos mínimos de acessibilidade estão documentados e testados.
- [ ] A documentação pública diferencia claramente beta, experimental e suportado.
- [ ] Nenhuma regressão ocorre nos cenários entregues pela `0.1.0-beta.1`.

## Fora do escopo

- Garantia de estabilidade equivalente a `1.0.0`.
- Suporte a todo navegador histórico capaz de interpretar ES5.
- Transformação de Aellux em framework visual ou substituto do Bootstrap.
- Inclusão automática de qualquer Extension de terceiro no bundle Core.
- SLA comercial ou suporte empresarial formal.

## Notas de versionamento

Enquanto o objetivo continuar sendo preparar a versão estável `0.1.0`, as prévias devem seguir `0.1.0-beta.1`, `0.1.0-beta.2`, `0.1.0-beta.3` e assim por diante. A versão `0.1.1-beta.1` deve ser usada somente quando `0.1.0` já representar uma linha anterior e o projeto estiver preparando as correções da futura `0.1.1`.
