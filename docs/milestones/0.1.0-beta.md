# Aellux 0.1.0 Beta

**Status:** Em desenvolvimento
**Versão alvo:** `0.1.0-beta.1`

## Objetivo geral

Validar o runtime, o sistema de extensões e a compatibilidade progressiva do Aellux em aplicações Web existentes, incluindo integração segura com Bootstrap, carregamento seletivo de extensões e um fallback Legacy com funcionamento mínimo em ES5.

## Escopo obrigatório

### Core e lifecycle das extensões

- [ ] Estabilizar o Core e o lifecycle das Aellux Extensions.
  - [ ] Garantir comportamento previsível de `init`, `mount`, `unmount` e `destroy`.
  - [ ] Garantir inicialização idempotente das extensões.
  - [ ] Garantir montagem idempotente, sem duplicar listeners ou recursos.
  - [ ] Permitir `$ae.update(root)` após alterações dinâmicas no DOM.
  - [ ] Garantir que `$ae.unmount(root)` libere os recursos associados aos elementos afetados.

### Registro e carregamento de extensões

- [ ] Consolidar o sistema de extensões.
  - [ ] Implementar e estabilizar `$ae.ext(...)`.
  - [ ] Implementar declaração via `<link rel="aellux-ext">`.
  - [ ] Suportar extensões carregadas imediatamente.
  - [ ] Suportar extensões carregadas sob demanda por seletor.
  - [ ] Remover extensões do índice lazy assim que seu carregamento for iniciado.
  - [ ] Evitar carregamentos duplicados ou concorrentes da mesma extensão.
  - [ ] Isolar falhas de uma extensão sem impedir a inicialização do orchestrator.

### Recursos opcionais por extensão

- [ ] Implementar carregamento opcional de estilos por extensão.
  - [ ] Permitir extensões somente JavaScript.
  - [ ] Permitir o carregamento do CSS associado quando declarado.
  - [ ] Aguardar os recursos necessários antes de concluir o `mount`.
  - [ ] Tratar falhas de CSS sem impedir o funcionamento JavaScript quando possível.

### Montagem visual

- [ ] Finalizar o comportamento de montagem visual.
  - [ ] Implementar `data-ae-wait-mounted`.
  - [ ] Implementar `data-ae-loader`.
  - [ ] Garantir que `ae--mounted` represente a conclusão das extensões e dos recursos necessários.
  - [ ] Remover `ae--mounted` durante o `unmount` quando aplicável.
  - [ ] Evitar conteúdo permanentemente bloqueado em caso de falha.

### Compatibilidade com Bootstrap

- [ ] Validar compatibilidade com Bootstrap.
  - [ ] Não depender de Bootstrap para executar o runtime.
  - [ ] Não interferir com classes, estilos ou comportamentos padrão do Bootstrap.
  - [ ] Evitar resets globais.
  - [ ] Evitar `preventDefault()` e `stopPropagation()` desnecessários.
  - [ ] Permitir coexistência de listeners do Bootstrap e do Aellux.
  - [ ] Testar Aellux dentro de componentes Bootstrap exibidos ou alterados dinamicamente.
  - [ ] Validar as utilities adaptativas que sobrepõem Bootstrap intencionalmente.
  - [ ] Criar ao menos uma página oficial de integração com Bootstrap.

### Seleção entre Modern e Legacy

- [ ] Implementar e validar a seleção entre Modern e Legacy no Aellux boot script.
  - [ ] Detectar as capacidades necessárias para selecionar o runtime adequado.
  - [ ] Carregar a distribuição Modern quando suportada.
  - [ ] Carregar a distribuição Legacy quando necessário.
  - [ ] Permitir forçar o modo Legacy para desenvolvimento e testes.
  - [ ] Emitir diagnóstico sobre capacidades ausentes e runtime selecionado.

### Distribuição Legacy

- [ ] Criar uma distribuição Legacy funcional.
  - [ ] Gerar código compatível com sintaxe ES5.
  - [ ] Incluir ou carregar os polyfills necessários para APIs utilizadas pelo Core.
  - [ ] Garantir suporte mínimo a `Promise` quando necessário.
  - [ ] Documentar quais APIs e ambientes fazem parte do suporte Legacy.
  - [ ] Não assumir que ES5 significa suporte irrestrito a qualquer navegador antigo.

### Variantes Legacy das extensões

- [ ] Suportar variantes Legacy das extensões.
  - [ ] Permitir uma extensão Modern e uma alternativa Legacy.
  - [ ] Fazer o Core escolher automaticamente a variante apropriada.
  - [ ] Definir uma convenção previsível de nomes ou URLs para builds Legacy.
  - [ ] Não exigir que cada extensão implemente sua própria detecção de ambiente.

### Contrato de compatibilidade das extensões

- [ ] Definir o contrato mínimo de compatibilidade das extensões.
  - [ ] Permitir extensões Modern-only, Legacy-only ou Modern + Legacy.
  - [ ] Detectar quando uma extensão não possui variante compatível com o runtime atual.
  - [ ] Emitir diagnóstico claro em caso de incompatibilidade.
  - [ ] Documentar os requisitos mínimos para uma Aellux Extension.

### Cenários de validação

- [ ] Validar os principais cenários de uso.
  - [ ] HTML e Web Platform sem framework visual.
  - [ ] Bootstrap.
  - [ ] Conteúdo inserido dinamicamente seguido de `$ae.update(root)`.
  - [ ] Extensão eager.
  - [ ] Extensão lazy.
  - [ ] Extensão com CSS.
  - [ ] Extensão sem CSS.
  - [ ] Runtime Modern.
  - [ ] Runtime Legacy forçado.
  - [ ] Extensão com builds Modern e Legacy.
  - [ ] Falha isolada de uma extensão durante carregamento ou inicialização.

### Degradação e diagnostics

- [ ] Garantir degradação previsível.
  - [ ] Tratar falhas no carregamento de scripts.
  - [ ] Tratar falhas no carregamento de estilos.
  - [ ] Não deixar elementos indefinidamente em estado de loading.
  - [ ] Encaminhar falhas para o sistema de diagnostics.
  - [ ] Manter a página utilizável sempre que houver fallback possível.

### Documentação da beta

- [ ] Documentar a compatibilidade da `0.1.0-beta`.
  - [ ] Explicar a diferença entre Modern e Legacy.
  - [ ] Explicar o nível de suporte ES5.
  - [ ] Documentar a integração com Bootstrap.
  - [ ] Documentar `$ae.ext(...)`.
  - [ ] Documentar `<link rel="aellux-ext">`.
  - [ ] Documentar carregamento lazy.
  - [ ] Documentar estilos opcionais das extensões.
  - [ ] Documentar variantes Legacy das extensões.
  - [ ] Documentar `data-ae-wait-mounted`, `data-ae-loader` e `ae--mounted`.
  - [ ] Revisar README, scaffold e exemplos oficiais.

## Critérios de aceitação da versão

- [ ] `npm run build` conclui sem erros.
- [ ] Os arquivos de distribuição e source maps estão sincronizados com `src/`.
- [ ] Os modos `basic` e `full` funcionam nos cenários documentados.
- [ ] O Aellux boot script seleciona corretamente entre Modern e Legacy.
- [ ] Extensões carregam, inicializam, montam e falham de forma independente.
- [ ] O contrato `mount` e `unmount` está consistente no Core, nas extensões e no scaffold.
- [ ] O CSS adaptativo é gerado a partir da configuração da Adaptive Extension.
- [ ] A integração oficial com Bootstrap passa nos testes definidos para a beta.
- [ ] Os cenários Modern, Legacy, eager, lazy, com CSS e sem CSS estão cobertos.
- [ ] Nenhuma falha conhecida deixa conteúdo permanentemente bloqueado.
- [ ] README, exemplos, templates, licença e changelog estão prontos para publicação.

## Fora do escopo

- Garantia de estabilidade de API equivalente a `1.0.0`.
- Suporte irrestrito a todos os navegadores capazes de interpretar ES5.
- Inclusão do Bootstrap ou de outros frameworks de terceiros no pacote Aellux.
- Promoção automática de componentes experimentais para o bundle Core.

## Notas

Este documento registra escopo planejado, decisões, bloqueios e critérios de conclusão. O `CHANGELOG.md` deve registrar apenas alterações efetivamente entregues.

O lifecycle público adotado pelo projeto usa `init`, `mount`, `unmount` e `destroy`. `$ae.update(root)` é a operação do orchestrator que solicita a montagem ou atualização idempotente dos elementos encontrados no escopo informado.
