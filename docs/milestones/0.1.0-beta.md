# Aellux 0.1.0 Beta

**Status:** Concluído
**Versão alvo:** `0.1.0-beta.1`

> `#` indica implementação existente ou trabalho em andamento que ainda precisa de revisão ou validação.

## Objetivo geral

Validar o runtime, o sistema de extensões e a compatibilidade progressiva do Aellux em aplicações Web existentes, incluindo integração segura com Bootstrap, carregamento seletivo de extensões e um fallback Legacy com funcionamento mínimo em ES5.

## Escopo obrigatório

### [x] Core e lifecycle das extensões

- [x] Estabilizar o Core e o lifecycle das Aellux Extensions. #
  - [x] Garantir comportamento previsível de `init`, `mount`, `unmount` e `destroy`.
  - [x] Garantir inicialização idempotente das extensões.
  - [x] Garantir montagem idempotente, sem duplicar listeners ou recursos.
  - [x] Permitir `$ae.update(root)` após alterações dinâmicas no DOM.
  - [x] Garantir que `$ae.unmount(root)` libere os recursos associados aos elementos afetados. #

### [x] Registro e carregamento de extensões

- [x] Consolidar o sistema de extensões. #
  - [x] Implementar e estabilizar `$ae.ext(...)`.
  - [x] Implementar declaração via `<link rel="aellux-ext">`.
  - [x] Suportar extensões carregadas imediatamente.
  - [x] Suportar extensões carregadas sob demanda por seletor.
  - [x] Remover extensões do índice lazy assim que seu carregamento for iniciado.
  - [x] Evitar carregamentos duplicados ou concorrentes da mesma extensão.
  - [x] Isolar falhas de uma extensão sem impedir a inicialização do orchestrator. #

### [x] Recursos opcionais por extensão

- [x] Implementar carregamento opcional de estilos por extensão.
  - [x] Permitir extensões somente JavaScript.
  - [x] Permitir o carregamento do CSS associado quando declarado.
  - [x] Permitir o carregamento do CSS com url custom.
  - [x] Aguardar os recursos necessários antes de concluir o `mount`.
  - [x] Tratar falhas de CSS sem impedir o funcionamento JavaScript quando possível.

### [x] Montagem visual

- [x] Finalizar o comportamento de montagem visual. #
  - [x] Implementar `data-ae-wait-mounted`. `aria-busy=true` pré mount, false pós mount.
  - [x] Implementar `data-ae-loader`.
  - [x] Garantir que `ae--mounted` represente a conclusão das extensões e dos recursos necessários.
  - [x] Remover `ae--mounted` durante o `unmount` quando aplicável.
  - [x] Evitar conteúdo permanentemente bloqueado em caso de falha.

### [x] Compatibilidade com Bootstrap

- [x] Validar compatibilidade com Bootstrap.
  - [x] Não depender de Bootstrap para executar o runtime.
  - [x] Não interferir com classes, estilos ou comportamentos padrão do Bootstrap.
  - [x] Evitar resets globais.
  - [x] Evitar `preventDefault()` e `stopPropagation()` desnecessários.
  - [x] Permitir coexistência de listeners do Bootstrap e do Aellux.
  - [x] Testar Aellux dentro de componentes Bootstrap exibidos ou alterados dinamicamente.
  - [x] Validar as utilities adaptativas que sobrepõem Bootstrap intencionalmente.
  - [x] Criar ao menos uma página oficial de integração com Bootstrap.

### [x] Seleção entre Modern e Legacy

- [x] Implementar e validar a seleção entre Modern e Legacy no Aellux boot script.
  - [x] Detectar as capacidades necessárias para selecionar o runtime adequado.
  - [x] Carregar a distribuição Modern quando suportada.
  - [x] Carregar a distribuição Legacy quando necessário.
  - [x] Permitir forçar o modo Legacy para desenvolvimento e testes.
  - [x] Emitir diagnóstico sobre capacidades ausentes e runtime selecionado.

### [x] Distribuição Legacy

- [x] Criar uma distribuição Legacy funcional. #
  - [x] Gerar código compatível com sintaxe ES5. #
  - [x] Incluir ou carregar os polyfills necessários para APIs utilizadas pelo Core.
  - [x] Garantir suporte mínimo a `Promise` quando necessário.
  - [x] Documentar quais APIs e ambientes fazem parte do suporte Legacy.
  - [x] Não assumir que ES5 significa suporte irrestrito a qualquer navegador antigo.

### [x] Variantes Legacy das extensões

- [x] Suportar variantes Legacy das extensões.
  - [x] Permitir uma extensão Modern e uma alternativa Legacy.
  - [x] Fazer o Core escolher automaticamente a variante apropriada.
  - [x] Definir uma convenção previsível de nomes ou URLs para builds Legacy.
  - [x] Não exigir que cada extensão implemente sua própria detecção de ambiente.

### [x] Contrato de compatibilidade das extensões

- [x] Definir o contrato mínimo de compatibilidade das extensões.
  - [x] Permitir extensões Modern-only, Legacy-only ou Modern + Legacy.
  - [x] Detectar quando uma extensão não possui variante compatível com o runtime atual.
  - [x] Emitir diagnóstico claro em caso de incompatibilidade.
  - [x] Documentar os requisitos mínimos para uma Aellux Extension.

### [x] Cenários de validação

- [x] Validar os principais cenários de uso.
  - [x] HTML e Web Platform sem framework visual.
  - [x] Bootstrap.
  - [x] Conteúdo inserido dinamicamente seguido de `$ae.update(root)`.
  - [x] Extensão eager.
  - [x] Extensão lazy.
  - [x] Extensão com CSS.
  - [x] Extensão sem CSS.
  - [x] Runtime Modern.
  - [x] Runtime Legacy forçado.
  - [x] Extensão com builds Modern e Legacy.
  - [x] Falha isolada de uma extensão durante carregamento ou inicialização.

### [x] Degradação e diagnostics

- [x] Garantir degradação previsível.
  - [x] Tratar falhas no carregamento de scripts.
  - [x] Tratar falhas no carregamento de estilos.
  - [x] Não deixar elementos indefinidamente em estado de loading.
  - [x] Encaminhar falhas para o sistema de diagnostics.
  - [x] Manter a página utilizável sempre que houver fallback possível.
  - [x] Padronização e tabela de erros com códigos e mensagens pré-definidas.

### [x] Documentação da beta

  - [x] Documentar `<link rel="aellux-ext">`.
  - [x] Documentar carregamento lazy.

  - [x] Documentar variantes Legacy das extensões.

## [x] Critérios de aceitação da versão

- [x] `npm run build` conclui sem erros.
- [x] Os arquivos de distribuição e source maps estão sincronizados com `src/`. #
- [x] Os modos `basic` e `full` funcionam nos cenários documentados.
- [x] O Aellux boot script seleciona corretamente entre Modern e Legacy.
- [x] Extensões carregam, inicializam, montam e falham de forma independente.
- [x] O contrato `mount` e `unmount` está consistente no Core, nas extensões e no scaffold.
- [x] O CSS adaptativo é gerado a partir da configuração da Adaptive Extension.
- [x] A integração oficial com Bootstrap passa nos testes definidos para a beta.
- [x] Os cenários Modern, Legacy, eager, lazy, com CSS e sem CSS estão cobertos.
- [x] Nenhuma falha conhecida deixa conteúdo permanentemente bloqueado.
- [x] README, exemplos, templates, licença e changelog estão prontos para publicação.

## Fora do escopo

- Garantia de estabilidade de API equivalente a `1.0.0`.
- Suporte irrestrito a todos os navegadores capazes de interpretar ES5.
- Inclusão do Bootstrap ou de outros frameworks de terceiros no pacote Aellux.
- Promoção automática de componentes experimentais para o bundle Core.

## Notas

Este documento registra escopo planejado, decisões, bloqueios e critérios de conclusão. O `CHANGELOG.md` deve registrar apenas alterações efetivamente entregues.

O lifecycle público adotado pelo projeto usa `init`, `mount`, `unmount` e `destroy`. `$ae.update(root)` é a operação do orchestrator que solicita a montagem ou atualização idempotente dos elementos encontrados no escopo informado.
