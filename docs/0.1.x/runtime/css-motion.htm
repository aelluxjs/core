CSS Motion Controller

aelluxJs.motion coordinates CSS transitions and CSS animations with waitLayout. CSS remains responsible for properties, keyframes, duration, delay, iterations and the normal CSS easing. In browsers with sufficient Web Animations API support, aellux.js pauses only the animations created by the requested state change and advances their currentTime from a monotonic clock. waitLayout.sequence() decides which frames perform those updates, including adaptive FPS reduction and the element's optional data-ae-maxfps limit.

The controller intentionally accepts a small main-thread cost under ideal conditions. Its purpose is predictable degradation: if the browser begins missing frames because of a constrained device or competing applications, the shared scheduler can reduce update frequency instead of allowing managed motion to contribute to stalls. A sustained severe delay selects the nearest compatible lower 15-FPS budget in one adjustment; an observed 10 FPS cadence reaches the 5 FPS floor immediately.

Controlled operations containing animated properties beyond transform, opacity, and Present's internal progress channels have a conservative default ceiling of 55 FPS. The exempt progress properties are --ae-pop-progress, --ae-dismiss-progress, --ae-unpop-progress, --ae-present-pop-phase, and --ae-present-dismiss-phase; arbitrary custom properties remain conservative because they can drive layout. Configure the ceiling with cssMotionPropertyMaxFPS in init(). This is a workload policy, not a promise that exempt properties stay on the GPU: browser composition and painting still depend on the document and device. Classification applies to the whole operation. If one transition combines opacity, transform, and height, all captured animations share one clock at the lowest applicable limit from data-ae-maxfps, run({ maxFPS }), and cssMotionPropertyMaxFPS; properties never receive independent schedules.

The shared scheduler applies that visual limit once, including before its native cadence has been calibrated. CSS Motion does not also impose a timer-based sequence limit: timer wakeups can miss the next animation frame and reduce a nominal 40 FPS operation to about 32 FPS on WebKit. Frame credit preserves the requested average cadence within the browser's available frames; it does not guarantee a frame rate when the device cannot sustain it.

The runtime's standard performance cadence for CSS publication is the shared adaptive waitLayout cadence, including when no CSS Motion operation is active. Direct publication of computed CSS values should use waitLayout.update(); it does not require motion.run(). The property ceiling described above is an additional controlled-motion policy, not a permanent global CSS-write ceiling. Direct CSSOM writes outside the scheduler do not automatically acquire adaptive protection. See CSS publication cadence and the authoring contract, including scheduled runtime publication and synchronous lifecycle boundaries.

$ae.init({
  mode: "full",
  cssMotionPropertyMaxFPS: 55
});

Use 0 or null to disable this special property ceiling. This does not disable the adaptive waitLayout scheduler or an element's data-ae-maxfps limit. Omitting the option (or passing undefined) retains the 55 FPS default.

const motionId = $ae.motion.id();
await $ae.motion.run(panel, {
  id: motionId,
  apply: () => panel.classList.add("open"),
  maxFPS: $ae.layoutMaxFPS(panel),
  abort: () => !panel.isConnected
});

run() returns { id, status, mode }. mode is "controlled", "native", or "reduced". A new operation with the same ID replaces the previous operation. $ae.motion.cancel(id) cancels owned scheduler work and releases captured animations.

Present reverse playback retains the original opening keyframes and easing, changes direction, and excludes the untravelled segment with a negative delay. It uses the same capture and adaptive clock as other motion. Its native completion waits only for newly owned effects, so unrelated existing infinite animations cannot hold a reverse request open. See opening reverse playback. Direction and negative-delay behavior follow Web Animations timing and CSS Animations.

Anchor target switches use the same adaptive scheduler and property FPS policy, with their own numeric geometry interpolation. A fixed origin and start time allow scroll, resize and layout updates to replace the destination without restarting native CSS transitions. Genuine target changes capture the rendered frame and start a new timeline. This path also works with cssMotionController: false or unavailable Web Animations APIs; it does not change this controller's public API. Ordinary placement tracking and native scroll/momentum remain independent. See Anchor.

Set subtree: true to capture new transitions and animations on the element and its descendants in the same operation. Existing effects remain outside its ownership. All captured effects share the same clock and FPS policy. Overflow Marquee uses this to synchronize a stationary viewport's fade offset with its child content's transform. The default captures only effects on the requested element.

Cancellation also settles a native operation as status: "aborted", even if an underlying Animation.finished Promise never settles. A failure partway through capturing multiple effects releases every effect already paused, resuming native playback before reporting the error. Completion or cancellation clears the operation's visual FPS ceiling. Native fallback leaves CSS playback under browser control; canceling the waiting operation does not claim ownership of unrelated native animations.

Native fallback and disabling control

Set the global initialization option cssMotionController to false to disable temporal control completely:

$ae.init({ mode: "full", cssMotionController: false });

The option defaults to true. When disabled, or when the browser lacks reliable getAnimations(), pause(), mutable currentTime, or computed timing, state classes and CSS are still applied normally. The controller does not pause frames, create a progress sequence, or impose a JavaScript FPS limit. No Web Animations polyfill is loaded.

Disabling CSS Motion timeline control does not disable the shared adaptive cadence for other CSS publications scheduled through waitLayout.

Advanced aellux.js easing

Controlled motion can opt into an easing name supported by $ae.ease(). When the browser accepts CSS linear(), the controller samples the aellux.js curve into a native timing function and lets the browser continue interpolating the CSS properties. Samples retain values outside 0..1, preserving Back and Elastic overshoot without applying the original CSS easing a second time.

Present reads --ae-pop-aellux-ease and --ae-dismiss-aellux-ease. Present effects read --ae-present-effect-aellux-ease from the effect target. Feedback only requests effects through present.effect.

.panel {
  --ae-pop-ease: ease-out;
  --ae-pop-aellux-ease: elasticOut;
}
.field { --ae-present-effect-aellux-ease: bounceOut; }

Always keep a valid CSS fallback such as linear, ease, ease-in, ease-out, or ease-in-out. Advanced aellux.js names are never inserted directly into CSS timing properties. If sampled linear() is unsupported, the declared CSS easing remains in effect. Reduced motion bypasses intermediate controlled frames while preserving state and completion lifecycle.
