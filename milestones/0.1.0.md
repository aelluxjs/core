# aellux.js 0.1.0

**Status:** em preparação; critérios de release pendentes

**Versão alvo:** `0.1.0`

**Versão atual do pacote:** `0.1.0-beta.6`

## Objetivo do release

Entregar um Core com contratos previsíveis de inicialização, carregamento, montagem, desmontagem, controllers e diagnostics, validado nos navegadores e ambientes declarados como suportados. Funcionalidade implementada ou documentada não equivale, por si só, a compatibilidade comprovada.

## Progresso desde a beta.1

O [milestone da beta.1](0.1.0-beta.1.md) registra a base entregue naquela versão; o [CHANGELOG](../CHANGELOG.md) registra as alterações versionadas até a beta.6. Os itens abaixo também incluem trabalho presente no repositório após a beta.6 e ainda sujeito aos critérios de release desta página. O milestone da beta.1 é histórico e contém nomes de API substituídos posteriormente; a [documentação da API atual](../docs-source/0.1.0/runtime/api.md) descreve o contrato vigente.

- [x] Estabelecer boot e distribuições `basic`/`full`, seleção Modern/Legacy, polyfills definidos, registro de Extensions por API ou HTML e carregamento eager/lazy com estilos opcionais.
- [x] Gerar bundles, variantes Legacy, arquivos minificados e source maps. A beta.6 retirou Adaptive do bundle Core; o estado atual do código voltou a incluí-la no bundle `full` e gera seu CSS pelo script de build.
- [x] Centralizar mapas de montagem no `mountManager`, oferecer controllers por elemento e padronizar os métodos públicos de montagem e desmontagem. `mount()` devolve os elementos recém-montados, sem duplicatas.
- [x] Registrar e restaurar `data-ae-*`, `aria-*` e `hidden` do elemento montado; limpar registros mesmo quando `unmount` não foi declarado. Limpar elementos destacados automaticamente quando `MutationObserver` existir e pela desmontagem global nos demais ambientes.
- [x] Validar `loadWhen` antes de registrar a Extension, diagnosticar seletores inválidos e repor `aria-busy="false"` após uma tentativa de montagem que falhe.
- [x] Manter Extensions no índice lazy até a inicialização bem-sucedida, compartilhar tentativas concorrentes e limpar a Promise de tentativas recuperáveis que falhem para permitir retry.
- [x] Organizar diagnostics por severidade, nível de verbosidade e histórico, com códigos para falhas dos contratos do Core.
- [x] Completar a matriz de regressão dos contratos do Core para normalização, builds, diagnostics, loading e retry, falhas do lifecycle, controllers, mapas, montagem parcial, atributos e limpeza de recursos e elementos destacados.
- [x] Implementar a Extension `point` como recurso separado do bundle `full`, com montagem de `data-ae-point`, limite de pointers, controller por elemento e eventos diretos, inclusive `PointerUp` ao ponto de origem após soltar fora dele. Há testes de navegador para esses fluxos.
- [x] Criar páginas próprias para as Extensions do Core e validar `state-navigation` simultaneamente na página pai e em um iframe, com histórico e eventos independentes.

Esses itens descrevem implementação existente. As tarefas pré-release abaixo bloqueiam a `0.1.0`; as pós-release ficam fora do suporte anunciado até serem concluídas e validadas.

## Pré-release: contratos e qualidade do Core

- [x] Criar CI obrigatória para instalação limpa, `npm run build`, `npm run test:browser`, `npm pack --dry-run` e verificação do diff; impedir a integração quando um desses passos falhar. O job `test` é exigido pela proteção da branch `main`, inclusive para administradores.
- [x] Executar e registrar a suíte completa em Chromium, Firefox e WebKit, incluindo as Extensions distribuídas separadamente, como `point`. A matriz registrada em 10 de outubro de 2026 aprovou 276 testes com Playwright 1.63.0 e publica as versões exatas dos engines testados.
- [x] Limitar o contrato Legacy de `0.1.0` ao bundle ES5 e ao fluxo forçado de seleção, fallback, polyfills e variantes de Extension nos engines desktop atuais da matriz Playwright. Não declarar suporte a versões históricas sem validação direta.

## Pré-release: escopo e integrações publicadas

- [x] Validar o uso simultâneo de `state-navigation` em iframe e página pai para `ajaxReplace` no iframe seguido de Voltar no iframe e depois no pai, em Chromium, Firefox e WebKit.
- [x] Substituir a dependência exclusiva de CDN no teste de Bootstrap por uma fixture local versionada, executar o teste de coexistência básica e limitar a documentação ao comportamento comprovado. O cenário usa localmente o CSS do Bootstrap 5.3.8, rejeita requisições externas e valida somente coexistência de CSS e namespaces.
- [ ] Definir requisitos mínimos de acessibilidade para as Extensions distribuídas e validar teclado, foco, estados ARIA, loaders e preferências de movimento, contraste e cor nos fluxos anunciados.
- [ ] Retirar `focus` dos artefatos distribuídos em `0.1.0` enquanto seus handlers permanecerem vazios; alinhar documentação e índice de Extensions ao pacote final.
- [ ] Declarar a matriz de suporte sem incluir ambientes mobile ainda não testados; revisar as referências preliminares a iOS Safari e Samsung Internet em `runtime/browser-support.md`. Manter `point` documentada e distribuída separadamente do bundle `full`.
