# aellux.js 0.1.0

**Status:** em preparação; critérios de release pendentes

**Versão alvo:** `0.1.0`

**Versão atual do pacote:** `0.1.0-beta.6`

## Objetivo do release

Entregar um Core com contratos previsíveis de inicialização, carregamento, montagem, desmontagem, controllers e diagnostics, validado nos navegadores e ambientes declarados como suportados. Funcionalidade implementada ou documentada não equivale, por si só, a compatibilidade comprovada.

## Progresso desde a beta.1

O [milestone da beta.1](0.1.0-beta.1.md) registra a base entregue naquela versão; o [CHANGELOG](../CHANGELOG.md) registra as alterações versionadas até a beta.6. Os itens abaixo também incluem trabalho presente no repositório após a beta.6 e ainda sujeito aos critérios de release desta página. O milestone da beta.1 é histórico e contém nomes de API substituídos posteriormente; a [documentação da API atual](../docs-source/0.1.0/runtime/api.md) descreve o contrato vigente.

- [x] Estabelecer boot e distribuições `basic`/`full`, seleção Modern/Legacy, polyfills definidos, registro de Extensions por API ou HTML e carregamento eager/lazy com estilos opcionais.
- [x] Gerar bundles, variantes Legacy, arquivos minificados e source maps. A beta.6 retirou Adaptive do bundle Core; o estado atual do código voltou a incluí-la no bundle `full` e gera seu CSS pelo script de build.
- [x] Centralizar mapas de montagem no `mountManager`, oferecer controllers por elemento e padronizar os métodos públicos de montagem e desmontagem. `mount()` devolve os elementos recém-montados, sem duplicatas.
- [x] Registrar e restaurar `data-ae-*`, `aria-*` e `hidden` do elemento montado; limpar registros mesmo quando `unmount` não foi declarado. Limpar elementos destacados automaticamente quando `MutationObserver` existir e pela desmontagem global nos demais ambientes.
- [x] Validar `loadWhen` antes de registrar a Extension, diagnosticar seletores inválidos e repor `aria-busy="false"` após uma tentativa de montagem que falhe.
- [x] Organizar diagnostics por severidade, nível de verbosidade e histórico, com códigos para falhas dos contratos do Core.
- [x] Implementar a Extension `point` como recurso separado do bundle `full`, com montagem de `data-ae-point`, limite de pointers, controller por elemento e eventos diretos, inclusive `PointerUp` ao ponto de origem após soltar fora dele. Há testes de navegador para esses fluxos.
- [x] Criar páginas próprias para as Extensions do Core e documentar explicitamente que o cenário de `state-navigation` em iframe ainda não está validado.

Esses itens descrevem implementação existente. A aprovação do release depende dos critérios pendentes abaixo, inclusive testes completos, compatibilidade declarada e revisão dos artefatos finais.

## Critérios pendentes: solidez do Core

- [ ] Criar CI obrigatória para instalação limpa, `npm run build`, `npm run test:browser`, `npm pack --dry-run` e verificação do diff; impedir a integração quando um desses passos falhar.
- [ ] Executar e registrar a suíte completa em Chromium, Firefox e WebKit, além de ao menos um ambiente mobile representativo. Corrigir falhas e publicar as versões de navegador efetivamente suportadas.
- [ ] Definir quais ambientes Legacy serão suportados e validar neles boot ES5, orchestrator, polyfills e variantes de Extension. Documentar as limitações observadas.
- [ ] Completar os testes de regressão dos contratos do Core: normalização e perfis de build; diagnostics; concorrência e retry do carregamento; falhas em cada etapa do lifecycle; controllers e mapas de montagem; restauração de atributos; limpeza de listeners, assets, scheduler e elementos destacados, com e sem `MutationObserver`.
- [ ] Decidir quando uma Extension sai do índice lazy, alinhar código e documentação à decisão e testar falha, retry, concorrência e destruição.
- [ ] Validar o contrato público de `mount()` que retorna elementos afetados, incluindo montagens parciais e falhas diagnosticadas, antes de fixá-lo para `0.1.x`.
- [ ] Testar `state-navigation` com iframe e página pai, incluindo Voltar/Avançar, recarga e sincronização de estado; implementar a comunicação necessária ou excluir explicitamente esse cenário do suporte de `0.1.0`.

## Integrações e acessibilidade

- [ ] Substituir a dependência exclusiva de CDN no teste de Bootstrap por uma fixture local versionada; testar componentes JavaScript, conteúdo exibido dinamicamente, coexistência de listeners e desmontagem.
- [ ] Definir requisitos mínimos de acessibilidade das Extensions oficiais e validar teclado, foco, estados ARIA, loaders e preferências de movimento, contraste e cor nos exemplos interativos.
- [ ] Definir o destino de `focus`, que ainda possui apenas handlers vazios: implementar comportamento e testes antes de anunciá-la como recurso, ou excluí-la dos artefatos publicados de `0.1.0`.
- [ ] Validar `point` na suíte completa e na matriz de suporte definida para o release; manter sua documentação e distribuição como Extension separada do bundle `full`.

## Distribuição e manutenção

- [ ] Medir tamanho normal e comprimido dos bundles e tempo de boot e atualização em cenários representativos; definir limites para as distribuições Modern e Legacy e verificar regressões na CI.
- [ ] Auditar dependências de build e licenças incorporadas, confirmar avisos obrigatórios nos artefatos e decidir se é necessário um `NOTICE` ou relatório de terceiros.
- [ ] Revisar carregamento de URLs e compatibilidade com CSP; documentar requisitos, limites de confiança de Extensions de terceiros e um canal de reporte de vulnerabilidades.
- [ ] Definir a política de compatibilidade e depreciação da API pública para a linha `0.1.x`, incluindo a classificação de APIs e Extensions experimentais.
- [ ] Atualizar a documentação de compatibilidade com a matriz comprovada, limitações conhecidas e escopo real da integração Bootstrap; revisar exemplos e links públicos.
- [ ] Definir o processo de publicação do pacote e dos artefatos de CDN, incluindo versionamento imutável, integridade quando aplicável e procedimento de rollback.
